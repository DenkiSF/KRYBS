# KRYBS — автоматизированная система резервного копирования с шифрованием по ГОСТ

**KRYBS** — консольная утилита для создания защищённых резервных копий файлов и баз данных PostgreSQL.  
Шифрование выполняется на основе блочного шифра «Кузнечик», а контроль целостности — с помощью хеш-функции «Стрибог».

Разработано в рамках дипломного проекта на языке Rust с упором на безопасность и потоковую обработку данных.

---

## Возможности

- **Источники данных:** файловая система, PostgreSQL (через `pg_dump`).
- **Шифрование на уровне приложения** блочным шифром «Кузнечик» в режиме CBC.
- **Envelope encryption** — мастер-ключ (KEK) шифрует ключ данных (DEK), что позволяет менять пароль без перешифрования архивов.
- **Контроль целостности** архива и каждого файла хеш-функцией «Стрибог» (256 бит).
- **Верификация** — быстрая (проверка структуры и расшифровки) и полная (сравнение хешей всех файлов).
- **Загрузка резервных копий в S3-совместимые хранилища** (AWS, MinIO и др.).
- **Двухфакторная аутентификация** (архитектурно поддерживается через PKCS#11, в текущей реализации ключ хранится в файле).
- **Автоматическое тестирование восстановления** (встроенная команда `verify`).
- **Иммутабельность** (поддержка WORM-хранилищ).

## Технологический стек

- Язык: **Rust** (edition 2024)
- Криптография: `libgost-rs` (Кузнечик), `streebog` (Стрибог)
- Архивация: `tar`, `flate2`
- CLI: `clap`
- Асинхронность: `tokio`
- Логирование: `log4rs`
- S3: `aws-sdk-s3`
- Сериализация: `serde`, `toml`

##Структура проекта (основные модули)
- cli – разбор аргументов командной строки
- config – работа с TOML-конфигурацией
- crypto – шифрование «Кузнечик», обёртка envelope encryption
- source – источники данных (файлы, PostgreSQL)
- backup – ядро: создание, восстановление, верификация
- storage – управление локальным хранилищем, S3-загрузка
- utils – хеширование, преобразование размеров, glob-фильтры
- logging – инициализация логирования с ротацией

##Формат контейнера резервной копии (KRYB)
Зашифрованная копия имеет магический заголовок KRYB и содержит:
- IV_KEK — вектор инициализации для расшифровки DEK
- Encrypted_DEK — ключ данных, зашифрованный мастер-ключом (48 байт)
- IV_DATA — вектор для расшифровки полезной нагрузки
- Ciphertext_Data — зашифрованный tar.gz-архив
